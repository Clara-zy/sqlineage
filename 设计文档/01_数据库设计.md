# SQLineage 数据库设计

> 版本: v2.0 | 数据库: PostgreSQL 15+  
> 变更: hash 缩短为 16 位 | 新增版本追踪表 | 废弃管理对齐自然语义模式

---

## 1. ER 概览

```
users ──< sessions

fields ──< field_references (自引用, DAG 有向边)

tables ──< table_input_subqueries   (输入子查询历史, 状态追踪)
tables ──< table_columns ──< table_column_mappings  (字段映射历史, 状态追踪)

subqueries ──> fields (select/union 引用的字段 hash)

natural_semantics ──> fields | tables | subqueries (三态多态关联, 状态追踪)
```

---

## 2. 核心原则

### 2.1 字段公民 = 客观逻辑

`fields` 表中的每一条记录描述一个客观存在的逻辑节点。**字段公民一旦创建，永不修改、永不物理删除**。即使上游链路重建，旧的字段节点依然保留在 DAG 中，只是不再被活跃的映射引用。

### 2.2 版本追踪 = 活跃 / 废弃

变动的不是字段公民本身，而是「其他公民对它的引用」：

| 谁引用什么 | 追踪表 | 含义 |
|---|---|---|
| 表 ← 子查询 | `table_input_subqueries` | 哪个子查询在向这张表写入 |
| 表列 ← 字段 | `table_column_mappings` | 该列当前映射到哪个字段节点 |
| 公民 ← 语义 | `natural_semantics` | 该节点的人类可读描述 |

三者均采用 `status ENUM('active','deprecated')` + `deprecated_at` + `deprecated_reason` 模式。

### 2.3 Hash = 16 位 hex

`sha256(canonical_jsonb(expression)).hex()[:16]` —— 约 64-bit 空间，百万级节点碰撞概率可忽略。

## 3. 逐表定义

### 3.1 `users` 用户表

| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |
| updated_at | TIMESTAMPTZ | | |

**初始数据**: `admin / nbkknb` (bcrypt)，角色 `admin`。

---

### 3.2 `sessions` 会话表

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| token | VARCHAR(256) | PK | 随机生成 |
| user_id | INT | FK → users(id), NOT NULL | |
| expires_at | TIMESTAMPTZ | NOT NULL | |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |

**索引**: `idx_sessions_user_id` ON `(user_id)`  
**策略**: 登录颁发，登出/超时硬删除。默认过期 24h。

---

### 3.3 `tables` 表结构定义

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | SERIAL | PK | |
| schema_name | VARCHAR(128) | NOT NULL | 库名 |
| table_name | VARCHAR(128) | NOT NULL | 表名 |
| logical_name | VARCHAR(256) | | 业务中文名 |
| table_type | VARCHAR(64) | NOT NULL | 事实表 / 维度表 / 汇总表 等 |
| source | ENUM('root','middle') | NOT NULL | |
| input_subquery_hash | VARCHAR(16) | FK → subqueries(hash) | **冗余指针**，指向当前 active 的输入子查询 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |
| updated_at | TIMESTAMPTZ | | |

**UNIQUE**: `(schema_name, table_name)`  
**索引**: `idx_tables_source` ON `(source)`

> `input_subquery_hash` 是冗余列，真实权威数据在 `table_input_subqueries` 中。读取时用此指针快速获取当前活跃值。

---

### 3.4 `table_input_subqueries` 表-输入子查询追踪

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | SERIAL | PK | |
| table_id | INT | FK → tables(id), NOT NULL | |
| subquery_hash | VARCHAR(16) | FK → subqueries(hash), NOT NULL | |
| status | ENUM('active','deprecated') | NOT NULL, DEFAULT 'active' | |
| deprecated_at | TIMESTAMPTZ | | |
| deprecated_reason | TEXT | | 如 "root→middle 升级，血缘链延长" |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |

**索引**: `idx_tis_table_status` ON `(table_id, status)`  
**应用层约束**: 每个 `table_id` 最多一条 `status='active'`

> 每次有新的 SQL 写入该表时：旧 active → deprecated，新建 active 记录，同时更新 `tables.input_subquery_hash` 冗余指针。

### 3.5 `table_columns` 表结构-列定义

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | SERIAL | PK | |
| table_id | INT | FK → tables(id), NOT NULL | |
| column_name | VARCHAR(128) | NOT NULL | 物理列名 |
| column_type | VARCHAR(64) | NOT NULL | 物理类型 |
| column_comment | VARCHAR(512) | | 建表 COMMENT |
| ordinal_position | INT | NOT NULL | 列顺序（建表语句中的声明顺序，从 1 开始） |
| field_hash | VARCHAR(16) | FK → fields(hash) | **冗余指针**，指向当前 active 映射的字段 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |
| updated_at | TIMESTAMPTZ | | |

**UNIQUE**: `(table_id, column_name)`  
**UNIQUE**: `(table_id, ordinal_position)`  
**索引**: `idx_tc_table` ON `(table_id)`

> `field_hash` 是冗余列，权威数据在 `table_column_mappings`。子查询 projection 必须按 `ordinal_position` 顺序对齐，构建时校验投影列数与表结构列数是否一致。

### 3.7 `fields` 字段公民 (DAG 节点)

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| hash | VARCHAR(16) | PK | `sha256(expression)[:16]` |
| field_type | ENUM('atomic','literal','expression','atomic_condition','composite_condition') | NOT NULL | |
| expression | JSONB | NOT NULL | 表达式树，子节点以 hash 引用 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |

**索引**: `idx_fields_field_type` ON `(field_type)`  
**索引**: `idx_fields_expression_gin` ON `(expression)` USING GIN

> **字段公民一旦创建，永不修改、永不物理删除。**

---

**字段类型与 expression 约定**:

```json
// atomic — 原子字段
{"op": "column", "table": "bs_comdb.trans_flow", "column": "mchnt_cd"}

// literal — 字面量
{"op": "literal", "value": "常量值", "type": "string"}

// expression — 普通运算 (op: + - * / concat substr nvl trim get_json_object ...)
{"op": "+", "args": [{"hash": "a1b2"}, {"hash": "c3d4"}]}

// expression — case_when
{"op": "casewhen", "args": [
  {"condition": "c1d2", "value": "e3f4"},
  {"condition": null, "value": "e5f6"}
]}

// expression — JOIN (一切 join 归约为此)
{"op": "JOIN", "args": [{"hash": "a1b2"}], "on": "c3d4"}

// expression — lateral (行转列)
{"op": "JOIN", "args": [{"hash": "a1b2"}], "on": "TRUE_HASH", "lateral": true}

// expression — groupby
{"op": "groupby", "args": [{"hash": "a1b2"}], "group_keys": ["d1e2", "d3e4"]}

// expression — window
{"op": "window", "args": [{"hash": "a1b2"}],
 "partition_by": ["d1e2"], "order_by": ["d3e4"], "frame": "ROWS BETWEEN ..."}

// expression — alias
{"op": "alias", "args": [{"hash": "a1b2"}], "alias_name": "at_per_num"}

// atomic_condition
{"op": "eq", "args": [{"hash": "L"}, {"hash": "R"}]}
// 其他 op: neq gt gte lt lte in not_in like is_null is_not_null

// composite_condition (CNF 标准化后有序)
{"op": "AND", "args": [{"hash": "c1"}, {"hash": "c2"}]}
{"op": "OR",  "args": [...]}
{"op": "NOT", "args": [{"hash": "c"}]}
```

---

### 3.8 `field_references` 字段引用关系 (DAG 边)

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| referenced_hash | VARCHAR(16) | FK → fields(hash) | 被引用节点 |
| referrer_hash | VARCHAR(16) | FK → fields(hash) | 引用节点 |

**PK**: `(referenced_hash, referrer_hash)`  
**语义**: `referenced → referrer`，数据从 referenced 流向 referrer  
**索引**: `idx_fr_referrer` ON `(referrer_hash)`

**一致性校验**: 每日定时任务遍历 DAG，对比 `fields.expression` 中的 hash 引用与 `field_references` 是否一致。

---

### 3.9 `subqueries` 子查询公民

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| hash | VARCHAR(16) | PK | `sha256(structure)[:16]` |
| subquery_type | ENUM('select','union') | NOT NULL | |
| structure | JSONB | NOT NULL | |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | |

**索引**: `idx_subqueries_type` ON `(subquery_type)`

**structure 约定**:

```json
// select 类型
{
  "type": "select",
  "fields": ["a1b2", "c3d4"],
  "where": "e5f6"
}

// union 类型
{
  "type": "union",
  "branches": ["s1q2", "s3q4"]
}
```

> join / groupby / having / aggregation 已下沉到字段公民。having 通过 `select + where` 嵌套处理。

## 4. 删除 / 废弃策略总览

| 表 | 策略 | 理由 |
|---|---|---|
| `fields` | **永驻** — 不修改、不物理删除 | 字段公民是纯逻辑，客观存在。废旧的节点不再被 active 映射引用即自然废弃 |
| `subqueries` | **永驻** — 不物理删除 | 同上 |
| `field_references` | **追加** — 随字段节点新建而增加 | DAG 边只增不减，历史链路完整保留 |
| `tables` / `table_columns` | **硬删除**（仅当无活跃引用时） | 表结构是物理索引，字段节点独立存在 |
| `table_input_subqueries` | **软废弃** (status=deprecated) | 历史输入可追溯 |
| `table_column_mappings` | **软废弃** (status=deprecated) | 历史映射可追溯 |
| `natural_semantics` | **软废弃** (status=deprecated) | 语义版本可追溯 |
| `users` / `sessions` | **硬删除** | 非核心业务数据 |

> **不引入 `deprecated_fields` 表**：避免与自然废弃（无 active 映射引用）产生不一致，单一真相来源原则。

---

## 5. 约束与注意事项

1. **Hash 16 位 hex**: `sha256 → hex[:16]`，约 8 字节 / 64-bit 空间。
2. **冗余指针**: `tables.input_subquery_hash` 和 `table_columns.field_hash` 是性能优化，真实权威数据在追踪表中。
3. **子查询 → 表列映射靠 ordinal_position**：子查询投影列与表结构列数必须相等，按 `ordinal_position` 逐位填入 `table_column_mappings`。列名可以不同。
4. **字段节点幂等**: 内容寻址天然去重，同一表达式不重复创建。
5. **root→middle 升级**: 级联重建 + 软废弃，详见 `05_血缘追溯升级设计.md`。
6. **Join / LIMIT 校验**: 入参阶段硬拒绝不规范的 join 写法和 LIMIT。
