# SQLineage 血缘追溯升级设计

> 版本: v1.0 | 模块: `upgrade_engine` | Python

---

## 1. 场景定义

当一张表 `source=root`（不可追溯），后来补充了其祖先链路，需要将其升级为 `source=middle`（可追溯），并级联刷新整条下游引用链。

这种场景在系统生命周期中极少发生（越接近末端的汇总表越容易发生，但下游较短），但处理必须**严格在一个事务中完成**。

---

## 2. 整体流程

```
┌─ Step 0: 准备 ─────────────────────────────────────────────────┐
│ 0.1 构建祖先表的表结构 (DDL → tables + table_columns)            │
│ 0.2 从 field_references 提取目标表的完整下游引用树               │
│ 0.3 快照当前 active 追踪记录 (供后续 deprecated)                 │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 1: 重建表血缘 ───────────────────────────────────────────┐
│ 1.1 临时修改目标表 source = middle                               │
│ 1.2 以 extended_sql 调用 LineageEngine.build()                   │
│     (此时目标表字段按 middle 逻辑走，沿祖先链生成新 field_hash)    │
│ 1.3 收集 projection 字段的 {old_hash → new_hash} 映射            │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 2: 级联刷新引用树 ───────────────────────────────────────┐
│ 2.1 初始化 global_mapping = projection 映射                     │
│ 2.2 对引用树做 BFS (拓扑序):                                     │
│     for each referrer_hash in reference_tree:                    │
│       old_expr = fields[referrer_hash].expression                │
│       new_expr = replace_sub_hashes(old_expr, global_mapping)     │
│       new_hash = sha256(canonical_json(new_expr))[:16]           │
│       if new_hash != referrer_hash:                              │
│         UPSERT fields(new_hash, new_expr)                        │
│         UPSERT field_references(子→new_hash)                     │
│         global_mapping[referrer_hash] = new_hash                 │
│       ELSE: (表达式未变) 跳过                                    │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 3: 级联刷新子查询 ───────────────────────────────────────┐
│ 3.1 对每个受影响的子查询 (structure 中引用了 global_mapping 中    │
│     的 hash):                                                    │
│     old_struct = subqueries[old_hash].structure                  │
│     new_struct = replace_sub_hashes(old_struct, global_mapping)   │
│     new_sq_hash = sha256(canonical_json(new_struct))[:16]        │
│     UPSERT subqueries(new_sq_hash, new_struct)                    │
│     global_mapping[old_sq_hash] = new_sq_hash                    │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 4: 软废弃旧追踪记录 ─────────────────────────────────────┐
│ 4.1 table_input_subqueries: 旧 active → deprecated              │
│     新 active (new_sq_hash)                                      │
│ 4.2 table_column_mappings: 旧 active → deprecated                │
│     新 active (new_field_hash，按 ordinal_position)              │
│ 4.3 更新 tables / table_columns 冗余指针                         │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 5: 自然语义迁移 ─────────────────────────────────────────┐
│ 5.1 遍历 global_mapping 中所有 old_hash:                         │
│     for each old_hash → new_hash (where old_hash ≠ new_hash):    │
│       old_semantics = SELECT FROM natural_semantics               │
│                       WHERE citizen_hash=old_hash AND status='active' │
│       if old_semantics exists:                                   │
│         — old_semantics → status='deprecated',                    │
│           deprecated_reason='root→middle 升级，语义迁移至 {new}'  │
│         — INSERT new natural_semantics(                          │
│             citizen_hash=new_hash, semantics=old.semantics,      │
│             source=old.source, status='active')                  │
│ 5.2 old_hash 没有 active 语义 → 不处理                            │
└────────────────────────────────────────────────────────────────┘
                          ↓
┌─ Step 6: 事务提交 ─────────────────────────────────────────────┐
│ 恢复目标表 source = middle (永久)                                │
│ COMMIT                                                           │
└────────────────────────────────────────────────────────────────┘
```

## 3. Step 2 详细说明 — 引用树级联

### 3.1 引用树提取

```
extract_reference_tree(root_hashes: list[str]) -> list[str]:
    """
    从 root_hashes (目标表的 projection field_hashes) 出发，
    BFS 遍历所有 referrer，收集完整的下游引用链。
    返回拓扑排序后的 hash 列表 (被引用者在前，引用者在后)。
    """
    visited = set()
    order = []
    queue = deque(root_hashes)
    
    while queue:
        h = queue.popleft()
        if h in visited: continue
        visited.add(h)
        order.append(h)
        
        # 找到所有引用 h 的节点
        referrers = SELECT referrer_hash FROM field_references
                    WHERE referenced_hash = h
        for ref in referrers:
            if ref not in visited:
                queue.append(ref)
    
    return order  # BFS 天然满足拓扑序
```

### 3.2 子 hash 替换

```
replace_sub_hashes(expression: dict, mapping: dict) -> dict:
    """
    递归遍历 expression JSONB，将其中所有的 hash 引用
    替换为 mapping 中的新 hash。
    """
    def replace(obj):
        if isinstance(obj, dict):
            result = {}
            for k, v in obj.items():
                if k == "hash" and isinstance(v, str) and len(v) == 16:
                    result[k] = mapping.get(v, v)  # 有映射则替换，无则保留
                else:
                    result[k] = replace(v)
            return result
        elif isinstance(obj, list):
            return [replace(item) for item in obj]
        else:
            return obj
    
    return replace(expression)
```

### 3.3 级联主循环

```
cascade_reference_tree(reference_order, global_mapping):
    for old_hash in reference_order:
        # 跳过已在 mapping 中的（投影层已处理）
        if old_hash in global_mapping and old_hash not in projection_hashes:
            # 已被前面的级联间接替换
            continue
        
        old_expr = query_field(old_hash).expression
        new_expr = replace_sub_hashes(old_expr, global_mapping)
        new_hash = sha256(canonical_jsonb(new_expr))[:16]
        
        if new_hash == old_hash:
            continue  # 未受影响，跳过
        
        # UPSERT 新字段节点
        UPSERT fields(hash=new_hash, field_type=old.field_type, expression=new_expr)
        
        # 写入新 field_references
        sub_hashes = extract_sub_hashes(new_expr)
        for sub_h in sub_hashes:
            UPSERT field_references(referenced=sub_h, referrer=new_hash)
        
        global_mapping[old_hash] = new_hash
```

## 4. 子查询级联 (Step 3)

```
cascade_subqueries(global_mapping):
    # 找出所有受影响的子查询
    affected_hashes = set()
    for old_hash in global_mapping:
        # 查找 structure 中包含此 hash 的子查询
        sqs = SELECT hash, structure FROM subqueries
              WHERE structure::text LIKE '%' || old_hash || '%'
        for sq in sqs:
            affected_hashes.add(sq.hash)
    
    for old_sq_hash in affected_hashes:
        old_sq = query_subquery(old_sq_hash)
        new_struct = replace_sub_hashes(old_sq.structure, global_mapping)
        new_sq_hash = sha256(canonical_jsonb(new_struct))[:16]
        
        if new_sq_hash != old_sq_hash:
            UPSERT subqueries(hash=new_sq_hash, type=old_sq.type, structure=new_struct)
            global_mapping[old_sq_hash] = new_sq_hash
```

## 5. 废弃记录参数

| 记录类型 | deprecated_reason 模板 |
|---|---|
| `table_input_subqueries` | `"root→middle 升级: 表来源从 root 变更为 middle，血缘链延长至 {ancestor_tables}"` |
| `table_column_mappings` | `"root→middle 升级: 字段链路已更新"` |
| `natural_semantics` | `"root→middle 升级: 语义迁移至 {new_hash}"` |

## 6. 事务边界与异常恢复

```
整个 upgrade 流程在一个数据库事务中执行:

BEGIN;
    try:
        Step 0 (准备)
        Step 1 (重建)
        Step 2 (字段级联)
        Step 3 (子查询级联)
        Step 4 (废弃旧记录)
        Step 5 (语义迁移)
        UPDATE target_table.source = 'middle'
    COMMIT;
    except AnyError:
        ROLLBACK;
        raise;
```

**事务大小预估**: 50 条下游链、每链 10 个字段节点 = 500 节点级联。每个节点约 1-3 条 SQL，事务总计约 1500 条 DML。PostgreSQL 单事务轻松承受。

## 7. API 入口

`POST /api/v1/lineage/upgrade` (详见 `02_API设计.md` 5.3)

**请求参数:**
- `table_id`: 待升级的表
- `ancestor_tables`: 祖先表的 DDL 列表 + source 标记
- `extended_sql`: 从祖先表到目标表的血缘 SQL

**响应:**
- `cascaded_fields`: 级联刷新的字段数量
- `new_fields`: 新建的字段节点数
- `deprecated_mappings`: 废弃的追踪记录数
- `old_to_new_map`: {old_hash: new_hash} 映射表

## 8. 同类场景扩展

同样的级联逻辑也适用于：

| 场景 | 触发条件 | 差异 |
|---|---|---|
| **表结构变更** | DDL 中列增删改 → `table_columns` 变化 | 目标表 source 不变，仅刷新 column_mappings + 下游引用树 |
| **写入 SQL 变更** | 同一张表的新 SQL 写入（逻辑不同） | 目标表 source 不变，但 projection 逻辑变了 → 下游级联 |

这两种场景复用同一套 `cascade_reference_tree` + `cascade_subqueries` 核心逻辑，仅触发入口和废弃原因不同。

```python
class UpgradeEngine:
    def upgrade_root_to_middle(
        self,
        table_id: int,
        ancestor_tables: list[AncestorTable],
        extended_sql: str,
        db: DatabaseSession
    ) -> UpgradeResult: ...

# upgrade_engine/cascade.py
class CascadeEngine:
    def extract_reference_tree(
        self, root_hashes: list[str], db: DatabaseSession
    ) -> list[str]: ...

    def cascade_fields(
        self, reference_order: list[str], global_mapping: dict, db: DatabaseSession
    ) -> None: ...

    def cascade_subqueries(
        self, global_mapping: dict, db: DatabaseSession
    ) -> None: ...

    def migrate_semantics(
        self, global_mapping: dict, reason: str, db: DatabaseSession
    ) -> None: ...

# upgrade_engine/replacer.py
class ExpressionReplacer:
    @staticmethod
    def replace_sub_hashes(expression: dict, mapping: dict) -> dict: ...

    @staticmethod
    def extract_sub_hashes(expression: dict) -> list[str]: ...
```
