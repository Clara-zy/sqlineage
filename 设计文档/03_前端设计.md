## 4. DAG 主工作台 `/` — 核心页面

这是系统的核心交互界面，承载血缘构建、可视化追溯、语义编辑功能。

### 4.1 布局

```
┌──────────────────────────────────────────────────────────┐
│  Toolbar: [输入SQL] [选择sink表] [构建血缘] [自动布局]     │
├────────────────────────────────┬─────────────────────────┤
│                                │                         │
│   ReactFlow DAG 画布           │  右侧面板 (可折叠)        │
│   - 字段节点                   │  - 节点属性               │
│   - 子查询节点 (可选叠加层)     │  - 语义编辑/确认         │
│   - 边 (引用关系)              │  - 上下游关系             │
│                                │                         │
├────────────────────────────────┴─────────────────────────┤
│  StatusBar: 节点数/边数 | 构建状态                         │
└──────────────────────────────────────────────────────────┘
```

### 4.2 组件树

```
WorkbenchPage
├── WorkbenchToolbar             — 顶栏：SQL 输入 + 构建触发 + 布局按钮
│   ├── SqlInput                 — 代码编辑器（textarea / 后续升级 monaco）
│   ├── SinkTableSelector        — 下拉选择目标表

```

### 4.3 FieldNode 自定义节点

ReactFlow Custom Node，根据 `field_type` 渲染不同样式：

| field_type | 颜色 | 图标 | 标签 |
|---|---|---|---|
| atomic | 🟢 绿 | ● | 表名.字段名 |
| expression | 🔵 蓝 | f(x) | 表达式类型 (op) |
| literal | ⚪ 灰 | " " | 截断的值 |
| atomic_condition | 🟡 黄 | == | 条件表达式 |
| composite_condition | 🟠 橙 | ∧∨ | AND/OR + 子条件数 |

**节点 Tooltip**: hover 显示完整表达式 + 自然语义（如有）  
**双击**: 聚焦该节点，SidePanel 展开属性  
**右键菜单**: 向上追溯 / 向下追溯 / 查看语义历史 / 复制 hash

### 4.4 ReferenceEdge 自定义边

- 带箭头实线
- hover 高亮上下游链路
- 点击选中 → 显示 from/to 节点摘要

### 4.6 Zustand Store 设计

```typescript
// useDagStore — DAG 画面状态
interface DagState {
  nodes: Node[];               // ReactFlow 节点
  edges: Edge[];               // ReactFlow 边
  selectedNode: FieldNode | null;
  sidePanelOpen: boolean;
  buildStatus: 'idle' | 'building' | 'done' | 'error';
  buildError: string | null;

  // Actions
  loadLineage: (rootHash: string, depth: number) => Promise<void>;
  buildLineage: (sql: string, sinkTable?: string) => Promise<void>;
  selectNode: (hash: string) => void;
  autoLayout: () => void;      // elkjs
  toggleSubqueryOverlay: () => void;
}

// useAuthStore — 认证状态
interface AuthState {
  token: string | null;
  user: User | null;
  login: (username: string, password: string) => Promise<void>;
  logout: () => void;
}
```

## 9. 交互流程图

### 9.1 血缘构建流程

```
用户输入 SQL → 点击"构建血缘"
    → POST /api/v1/lineage/build
    → 后端校验 (LIMIT / JOIN / 表结构 / hash)
        失败 → 显示错误 + 红色高亮违规部分
        成功 → 返回 { new_fields, new_subqueries, ... }
    → useDagStore 更新 nodes/edges
    → elkjs 自动布局
    → 画布渲染新 DAG
    → StatusBar 显示 "构建完成: +15 新节点, 复用 42 节点"
```

### 9.2 语义编辑流程

```
点击节点 → SidePanel 显示属性
    → [AI 推断] 按钮 (expert/admin only)
        → POST /api/v1/semantics/ai-infer
        → 显示推断结果 + 置信度
        → [确认] / [放弃]
            → POST /api/v1/semantics/ai-confirm
    → [修改] 按钮
        → 手动编辑区
        → [保存] → PUT /api/v1/semantics/{hash}
```

### 9.3 输入/映射历史查看

```
表详情页 → 点击列 → 弹出映射历史面板
    → GET /api/v1/tables/{id}/columns/{col_id}/mapping-history
    → 展示 active + deprecated 列表（field_hash / 状态 / 时间 / 废弃原因）

表详情页 → [查看输入历史]
    → GET /api/v1/tables/{id}/input-history
    → 展示 active + deprecated 列表（subquery_hash / 状态 / 时间 / 废弃原因）
```

### 9.4 血缘追溯升级流程 (admin only)

```
表详情页 → [升级为 middle] (仅 root 表可见)
    → 弹出升级弹窗
        ├─ 输入祖先表 DDL (可多条，逐条添加)
        └─ 输入 extended_sql (连接祖先表到目标表的血缘 SQL)
    → [提交]
        → POST /api/v1/lineage/upgrade
        → 显示 loading (级联可能耗时)
        → 成功: 展示级联统计
            { cascaded_fields, new_fields, deprecated_mappings, ... }
        → 失败: 展示错误信息 (事务已回滚)
```

## 10. 技术实现要点

1. **React Flow 节点数优化**: 大血缘图（>500节点）时用虚拟化 + 按需加载（初始加载目标节点 ± N 层，滚动/点击时增量加载）
2. **elkjs 自动布局**: 构建完成后自动触发分层布局（layered），用户也可手动拖拽
3. **子查询叠加层**: 默认隐藏，通过开关显示虚线框将同一子查询的字段分组
4. **深色/浅色主题**: Tailwind dark mode class 切换
