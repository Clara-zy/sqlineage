# SQLineage AI 语义推断设计

> 版本: v1.0 | 模块: `ai_semantics`

---

## 1. 核心流程

```
推断(字段 field_hash):
    1. 读取 fields.expression
    2. 提取 expression 中所有子 hash 引用
    3. 逐个查询 natural_semantics (citizen_hash = sub_hash, status = 'active')
        ├─ 全部存在 → 用语义文本替换 hash 占位
        └─ 任一缺失 → 终止，返回 "请先补充上游节点 {hash} 的语义"
    4. 拼装 prompt：字段类型 + 替换后的表达式描述
    5. 调用 LLM，返回推断语义 + 置信度
    6. 结果返回前端展示，不直接写入
```

---

## 2. 表达式 → 自然语言化

### 2.1 逐类型转换规则

| field_type | 转换方式 |
|---|---|
| `expression` | `{op}({替换后的 args})` |
| `atomic_condition` | `{op}(左, 右)` 如 `等于(交易金额, 退款金额)` |
| `composite_condition` | `{op}(子条件1, 子条件2)` 如 `且(条件A, 条件B)` |

### 2.2 特殊字段的额外信息

| op | 额外拼入的信息 |
|---|---|
| `JOIN` | `on: {替换后的 on 条件语义}` |
| `groupby` | `分组维度: {替换后的 group_keys 语义}` |
| `window` | `分区: {partition_by} / 排序: {order_by} / 范围: {frame}` |
| `alias` | `别名: {alias_name}` |
| `casewhen` | `条件1: {语义1} → 取值1: {取值1语义}, ...` |

### 2.3 子查询 / 表

子查询和表的 AI 推断不需要递归替换——直接用 `structure` 中的字段 hash 查语义即可，流程一致。

---

## 3. Prompt 模板

```
你是一个数据血缘分析专家。请根据以下字段表达式信息，推断该字段的自然语言语义。

字段类型: {field_type}
表达式描述: {expression_text}

请返回 JSON:
{ "semantics": "推断的中文语义（简洁，≤20字）", "confidence": 0.0-1.0 }
```

---

## 4. API 对接

接口 `POST /api/v1/semantics/ai-infer`（见 `02_API设计.md` 7.3）

```
Request:  { "citizen_hash": "a1b2", "citizen_type": "field" }
Response: { "inferred_semantics": "净交易金额(元)", "confidence": 0.92,
            "reasoning": "由子节点'交易金额' + '退款金额'推导" }
```

---

## 5. 边界条件

| 场景 | 处理 |
|---|---|
| 上游语义缺失 | 终止，返回 `{ "error": "missing_upstream", "missing": ["hash1", "hash2"] }` |
| LLM 超时 / 不可用 | 返回 `{ "error": "llm_unavailable" }`，不重试 |
| `literal` 类型 | 无需 LLM，表达式描述本身即语义，直接返回 |
| `atomic` 类型 | 无需推断——原子字段语义应来自表结构 COMMENT |
